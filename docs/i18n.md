# Internacionalización (i18n)

Dos cosas distintas, deliberadamente separadas:

| | Qué es | Dónde se configura | Dónde vive |
|---|---|---|---|
| **Idioma de la interfaz** | El texto de VELUM | Configuración → Idioma | `uiLanguage` en `config.json` |
| **Idioma de los datos de Steam** | Parámetro `l` de la Web API (nombres/descripciones de logros) | Configuración → Cuentas | `steamLang` en `config.json` |

Son ajustes separados porque son decisiones distintas: hay quien quiere la
interfaz en español y los logros en inglés. El segundo arranca en `"auto"` =
seguir al primero, que es la preselección que hace la configuración inicial.

Idiomas soportados: **es-419** (Latinoamérica, canónico), **es-ES** (España),
**en-US**.

## Runtime

`src/lib/i18n/index.js` — implementación propia, ~90 líneas, sin dependencias.

```svelte
<script>
  import { t, fmt } from "../i18n/index.js";
</script>

<h1>{$t("settings.language.title")}</h1>
<p>{$t("steam.lang.auto", { value: "English" })}</p>
<span>{$fmt.time(new Date())}</span>
```

- **En componentes**: `$t("clave", vars)`. Es un store derivado de `locale`, así
  que cambiar el idioma re-renderiza todo lo que lo use, sin recargar.
- **En stores/funciones**: `tr("clave", vars)` — imperativo, NO reactivo. Para
  mensajes que se arman una sola vez (toasts, errores). El texto queda
  congelado: si el idioma cambia con un toast en pantalla, se queda en el
  anterior durante sus 2,2 s. Aceptable.
- **Fechas/horas/números**: `$fmt.time / .date / .dateTime / .number`. Nunca
  `toLocaleTimeString()` a pelo — y **nunca** `.slice(0, 5)` sobre el
  resultado: rompe en locales de 12 h (deja `"3:45:"`).

Los 3 diccionarios se importan estáticamente (~20 KB gzip): el idioma está
disponible antes del primer pintado, sin estado "cargando" ni carrera con los
`init*()` de `App.svelte`.

**Fallback en cascada**: idioma activo → `es-419` → la clave literal. Nunca
queda un hueco en blanco. En dev, la consola avisa una vez por clave faltante
(`[gm:i18n] clave sin traducción: …`).

## Convención de claves

`namespace.subnamespace.slug`, en `src/lib/i18n/locales/*.js`. Claves **planas
con puntos** (no anidadas) para que `grep "settings.language.title"` encuentre
a la vez la definición y todos los usos.

Sufijos estandarizados:

| Sufijo | Uso |
|---|---|
| `.title` | Encabezado de panel/modal |
| `.desc` | Párrafo explicativo bajo el título |
| `.label` | Etiqueta de un control |
| `.action` | Texto de un botón |
| `.hint` | Nota secundaria / pie |
| `.empty` | Estado vacío |
| `.confirm` | Pregunta de confirmación |
| `.aria` | `aria-label` |
| `.options.<id>` | Etiqueta de un valor de enum |

### Regla de oro: los ids no se traducen ni se renombran

Muchos ids persistidos están en español (`DETAIL_SECTIONS = ["grupos",
"imagenes", …]`, `system-actions`, `infinito`). **Son datos guardados en la
config del usuario**: renombrarlos rompe instalaciones existentes en silencio.

La clave usa el id tal cual: `settings.sections.system-actions`,
`detail.sections.grupos`. Los ids son datos, las etiquetas son claves.

### Registro: es-419 es LATAM **neutro**

Nada de voseo rioplatense. El canónico usa **tuteo neutro**, que es lo que ya
usaba el resto de la app:

| ✗ Voseo (Argentina/Uruguay) | ✓ Neutro |
|---|---|
| Elegí, seleccioná | Elige, selecciona |
| Podés, tenés, querés | Puedes, tienes, quieres |
| Agregá, cambiá, vinculá | Agrega, cambia, vincula |

Y neutro también en vocabulario: **computadora** (no "ordenador"), **celular**
(no "móvil"), **video** (no "vídeo"), **presionar** (no "pulsar").

Consecuencia esperada: muchas cadenas de `es-419` y `es-ES` quedan **idénticas**
—ambos usan tuteo, así que la conjugación no los separa. Lo que los diferencia
es el vocabulario de la tabla de arriba y el código de idioma de Steam. Cuando
no haya diferencia, se repite la cadena tal cual: duplicar sale más barato que
montar herencia entre idiomas.

> El texto original hardcodeado del modal de primer arranque estaba en voseo
> ("Elegí qué tiendas mostrar", "Podés cambiarlo"); era el outlier del repo y
> se normalizó al migrarlo. Si aparece más voseo en las tandas siguientes, se
> normaliza igual — es la única excepción a la regla de "copiar el texto
> idéntico" al construir el diccionario canónico.

### Plurales

Cualquier cadena con un número variable se declara como objeto, **aunque hoy en
español el texto sea igual en singular y plural** — si no, traducir a un idioma
nuevo obliga a volver a tocar código:

```js
"steam.toast.librarySynced": {
  one: "Biblioteca sincronizada: {count} juego",
  other: "Biblioteca sincronizada: {count} juegos",
},
```

Se resuelve con `Intl.PluralRules`. es/en usan `one`/`other`; un idioma con
`few`/`many` entra sin tocar el runtime. Prohibido el viejo `juego(s)`.

### Nunca concatenar

```js
"Última vez: " + fecha        // ✗ en inglés cambian orden y puntuación
$t("detail.lastPlayed", { when: $fmt.dateTime(d) })   // ✓
```

Y las funciones auxiliares que usen `$t`/`$fmt` tienen que ser **reactivas**
(`$: fn = (x) => …`), no `function fn(x)`, o no se recomputan al cambiar de
idioma. Lo mismo para los stores `derived` que emitan etiquetas: hay que
incluir `t` entre sus dependencias.

## Agregar una cadena

1. Clave nueva en `locales/es-419.js` con **el texto exacto** que estaba
   hardcodeado (es el idioma canónico: migrar debe ser un refactor sin cambio
   visible, revisable comprobando que cada cadena borrada reaparece igual). La
   única excepción: si el original usa voseo, se normaliza — ver "Registro".
2. La misma clave en `es-ES.js` y `en-US.js`.
3. `npm run i18n:check`.

## Agregar un idioma

1. Entrada en `UI_LOCALES` (`src/lib/i18n/index.js`) con `id`, `label`
   (autónimo), `steamLang` (código de Steam asociado) e `intl` (tag BCP-47).
2. `locales/<id>.js` con todas las claves.
3. Mapeo en `detectOsLocale()` (`src/lib/stores/language.js`).
4. `npm run i18n:check`.

Los idiomas de **Steam** son otra lista: `src/lib/i18n/steamLanguages.js`, los
~29 códigos de Steamworks, estática porque Steam no expone ningún endpoint que
los liste. Se muestran con autónimos para no tener que traducir 29 nombres por
cada idioma de interfaz.

## Verificación

```bash
npm run i18n:check            # paridad de claves, claves usadas sin definir, plurales sin "other"
node scripts/i18n-check.mjs --unused   # además, claves definidas y nunca usadas
```

**Truco de QA canónico**: poner la interfaz en **English** y recorrer la
pantalla — todo lo que quede en español es, por definición, código sin migrar.

## Errores del backend

Rust no traduce: devuelve **códigos estables** que resuelve el frontend.

```rust
Err("steam.invalid_key".into())
Err(format!("steam.key_read_failed|{e}"))   // código|detalle, partido en el PRIMER |
```

```js
// src/lib/i18n/errors.js — lo aplica reportError() en stores/ui.js
"errors.steam.invalid_key": "API key o SteamID inválidos",
"errors.steam.key_read_failed": "No se pudo leer la API key guardada: {detail}",
```

Lo que no tenga forma de código se muestra crudo: los errores de JS del
frontend, los de red del WebView y cualquier mensaje sin migrar siguen siendo
legibles. Los `println!` de Rust son diagnóstico, no UI — no se traducen nunca.

## Caché de Steam y cambios de idioma

`achievement_schema` y `schema_cache` (SQLite) llevan una columna **`lang`**
que dice en qué idioma está el texto guardado. **No forma parte de la PK** a
propósito: meterla obligaría a recrear las tablas, y eso reasignaría los
`rowid`, de los que depende el orden de los logros bloqueados en el Detalle.

Consecuencias:

- Hay **una fila por logro**, con el texto del último idioma pedido.
- Cambiar el idioma **no dispara ni una llamada de red**. Los textos se
  actualizan a medida que cada juego entra en una sincronización, de golpe con
  "Sincronizar ahora", o por juego con "Sincronizar logros" del Detalle.
- Los juegos **sin** logros nunca se re-piden por un cambio de idioma (no hay
  texto que traducir) — son la mayoría de una biblioteca.
- Se guarda el idioma **pedido**, no el servido: si el fallback cayó a inglés
  porque el juego no está traducido, la fila igual dice el idioma pedido. Si
  no, cada sync vería "idioma distinto" y re-pediría el esquema para siempre.

Ver `schema_text_is_stale` y `sync_one_game` en
`src-tauri/src/steam_api/achievements.rs`.
